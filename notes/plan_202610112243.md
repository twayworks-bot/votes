## 1. 최소 기능 제품 (MVP, Minimum Viable Product) 정의

### 1.1 MVP 개요 및 핵심 가치
VoteEvent 플랫폼의 MVP 핵심 가치는 **"누구나 손쉽게 투표 행사를 개설/참여하고, 관리자 전용 권한과 프라이버시가 엄격히 보호되며, 원격 중앙 인증(Keycloak)과 로컬 개발 환경 모두에서 끊김 없고 안전한 사용자/관리자 경험을 제공하는 웹 서비스"**입니다.

### 1.2 핵심 MVP 기능 구성도

```mermaid
flowchart TD
    subgraph Client["브라우저 클라이언트"]
        Btn["관리자 버튼 클릭<br/>(새 이벤트 개설 / 수정 / 삭제 / 로그인)"]

        LoopBreaker["Loop Breaker Guard<br/>(auth_attempted 검사)"]
        AdminPages["관리자 페이지<br/>(/votes/create, edit, delete)"]
    end
```

### 1.3 MVP 상세 기능 스펙
1. **이벤트 수명주기 및 불변성 보장**:
   - 이벤트 활성/마감 상태에 따른 항목 생성, 수정, 삭제, 투표 엄격 제어.
   - 마감 이벤트 접근 시 모든 변경 기능 `disabled` 및 서버 400 차단.
2. **원격 중앙 인증 및 환경변수 주입**:
   - Dockerfile 환경변수 `AUTH_URL` 및 `AUTH_VERIFY_URL`을 앱 설정에 완벽 바인딩.
   - `verify_admin_session(auth_session)` 비동기 클라이언트 호출로 매니저 여부 정밀 확인.
3. **내부 사전 검증 및 로컬 리다이렉션 개선**:
   - 관리자 기능 실행 전 브라우저에서 `/votes/api/auth/status`를 호출하여 매니저 권한 사전 검증.
   - 이미 매니저로 인증된 경우 원격 로그인 페이지 리다이렉션 없이 대상 URL로 직행.
   - 미인증 시 `window.location.origin`을 포함한 완전한 URL을 `redirect` 쿼리로 전달하여 로컬 개발 환경 복귀 보장.
4. **무한 루프 차단 가드 (Loop Breaker)**:
   - 서버 측 `require_manager_web`에서 303 리다이렉션 시 `auth_attempted=1` 파라미터를 부착하여 2차 반복 시 403 Forbidden 페이지를 렌더링하여 무한 루프 원천 차단.

## 2. 개발 세부 요구 계획 (Detailed Implementation Plan)

### 단계 1: 환경변수 정의 및 설정 모듈 동기화
- `Dockerfile`에 `ENV AUTH_VERIFY_URL=${AUTH_URL}/api/verify-session` 명시.
- `app/core/config.py`에서 `AUTH_VERIFY_URL = os.getenv("AUTH_VERIFY_URL", f"{AUTH_URL}/api/verify-session").strip()` 로직 반영.

### 단계 2: 백엔드 인증 계층 및 사전 검증 API 고도화
- `app/core/auth.py`:
  - `verify_admin_session(auth_session: str) -> bool` 비동기 함수 구현 (`httpx.AsyncClient` 4.0초 타임아웃, 예외 처리).
  - `require_manager_web(request)`를 `async def`로 리팩터링하고, `verify_admin_session` 호출 및 `auth_attempted` 가드 적용.
- `app/routers/admin_router.py`:
  - `GET /votes/api/auth/status` 엔드포인트를 구현하여 클라이언트 세션 토큰(쿠키, 헤더, 쿼리) 검증 및 JSON 응답(`{authenticated, is_manager, username, role}`) 반환.
  - 관리자 뷰 라우터 핸들러(`create_event_page`, `edit_event_page`, `delete_event_action`) 비동기 통일.

### 단계 3: 프론트엔드 사전 검증 및 분기 처리 구현
- `app/templates/base.html`:
  - 전역 스크립트에 `handleManagerAction(event, targetPath, onSuccessCallback)` 함수 구현.
  - 브라우저 쿠키, `sessionStorage`, `localStorage`, URL 파라미터에서 `auth_session`을 수집하여 `/votes/api/auth/status`로 검증.
  - 인증 성공 시 로컬 쿠키 동기화 후 타겟 경로로 직접 이동.
  - 비인증 시 `window.location.origin`을 접두사로 붙인 완전한 복귀 URL을 생성하여 Keycloak 로그인 페이지로 리다이렉트.
- `app/templates/admin/event_list.html`:
  - 상단 "새 이벤트 개설", 빈 목록 "새 이벤트 개설" 버튼에 `onclick="return handleManagerAction(event, ...)"` 적용.
  - 각 이벤트 카드의 "수정" 및 "삭제" 버튼에 `handleManagerAction` 적용.
  - 비인증 상태의 "관리자 로그인" 버튼에 `handleManagerAction` 적용.

### 단계 4: 테스트 및 검증
- 단위/통합 테스트(`tests/test_vote_event.py`)를 통해 다음 시나리오 검증:
  - Dockerfile 및 설정 환경변수 로딩 검증
  - `verify_admin_session` 모의 호출 및 세션 유효성 판별 검증
  - `/votes/api/auth/status` 비동기 응답 검증
  - 관리자 버튼 사전 검증 및 리다이렉션 흐름 검증
  - 무한 루프 차단 가드(Loop Breaker) 403 반환 검증
