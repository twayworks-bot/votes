## 1. 사용자 원본 요구사항 (User Raw Requests)

### [요구사항 1] 종료된 이벤트의 생성 및 투표 차단
> "이 프로젝트는 선호도를 조사하는 투표 시스템입니다. 선호도 조사를 위한 투표 이벤트를 생성하고, 각 항목을 생성하고 생성된 각 항목에 대한 선호도(좋아요)를 투표합니다. 투표 이벤트를 생성한 후 이벤트의 투표를 종료 했지만, 이벤트의 하위 항목이 생성되고 선호도 투표도 계속 진행이 됩니다. 이벤트 종료로 설정이 되면 생성버튼과 선호도 투표진행이 더 이상 진행이 되지 않도록 버튼을 disable 시키거나 숨겨주세요. 내용을 검토 후 수정사항을 반영해 주세요."

### [요구사항 2] 종료된 이벤트 항목의 수정 불가
> "종료된 이벤트의 경우 등록된 항목에 대한 수정도 불가합니다. 현재 항목에 대한 수정이 가능합니다. 수정해 주세요."

### [요구사항 3] 종료된 이벤트 항목의 삭제 불가
> "종료된 이벤트의 경우 "삭제하기"버튼도 disable 시켜주세요."

### [요구사항 4] Keycloak 세션 비동기 검증 및 환경변수(AUTH_URL) 참조
> "다른 서비스에서 구현했던 코드를 참조 하여 manager여부를 검증해서 웹서비스에서 manager로그인여부를 확인하시오.
> ```python
> # Keycloak Session Verification Endpoint using the new domain holyseeds.thewayworks.net
> AUTH_VERIFY_URL = "https://holyseeds.thewayworks.net/auth/api/verify-session"
>
> async def verify_admin_session(auth_session: str) -> bool:
>     """Validate user credentials and check for manager status using Keycloak API Proxy."""
>     if not auth_session:
>         return False
>     try:
>         async with httpx.AsyncClient() as client:
>             response = await client.get(
>                 AUTH_VERIFY_URL,
>                 params={"session_id": auth_session},
>                 timeout=4.0
>             )
>             if response.status_code == 200:
>                 result = response.json()
>                 return result.get("valid") is True and result.get("is_manager") is True
>     except Exception as e:
>         print(f"[Auth Error] Failed to verify Keycloak session: {e}")
>     return False
> ```
> Dockerfile에 정의된 환경변수(AUTH_URL)를 참조하거나 기본값을 기반으로 검증하도록 해주세요. 현재 구현된 코드는 로컬로 로그인하는 경우 로그인 검증 없어서 로그인 상태를 확인할 수 없습니다."

### [요구사항 5] 이벤트 옵션 ("관리자만 연결", "좋아요 횟수 숨기기") 추가
> ""새 이벤트 개설"이나 생성된 이벤트의 "수정"시 해당 이벤트를 바로 연결할수 있는 ENDPOINT URL에 대한 접속은 기본적으로 누구나 접근이 가능하지만, 이벤트의 옵션 기능 중 "관리자만 연결" 선택 기능이 있어서, 이 옵션이 활성화되면 해당 이벤트는 관리자권한만 접근이 가능한 이벤트로 지정되어, 일반 사용자나 익명사용자는 접근이 허용되지 않는다고 메세지를 띄워주세요. 이벤트 항목 카드에는 "관리자만 접근"에 해당하는 tag (혹 아이콘)을 추가 해주세요. 추가로 이벤트 옵션에 "좋아요"(favorite) 횟수 숨기 옵션이 있어서, 이 경우 일반 사용자는 "좋아요" 횟수를 볼 수 없습니다. 추가된 요구사항을 반영해 주세요."

### [요구사항 6] 관리자 기능 호출 시 내부 사전 검증(`verify_admin_session`) 및 로컬 리다이렉션 개선
> "다음과 같이 "새 이벤트 개설"에 대한 login 인증을 할 때, "https://holyseeds.thewayworks.net/auth/login?redirect=/votes/create&require_role=manager" 와 같이 검증과 동시에 버튼을 실행하면, local 개발 서비스 상태에서는 로그인 상태를 확인하기 어렵고 다시 localhost로 redirection이 되지 않는 문제가 있습니다. local 테스트의 경우 원격서버에 로그인이 되어 있으면 사전 검증 절차로 redirection URL을 통해 검증을 하지 않도록 수정이 필요합니다.
> 즉, 사전에 내부 시스템에서 "verify_admin_session" login 인증을 한번 하고, 인증 세션이 검증된 상태이면, 바로 "/votes/create"를 부르고 인증이 안된 상태이면 "https://holyseeds.thewayworks.net/auth/login?redirect=/votes/create&require_role=manager"를 호출하도록 수정이 필요합니다. 관리자 검증 후 관리자가 아니면 호출 버튼에서 동일하게 manager 검증을 위한 redirection url을 연결하도록 구현하시오."

### [요구사항 7] localhost redirection 무한 루프(303 See Other) 원인 분석 및 해결
> "localhost 개발 테스트 중에 manager인증절차를 검증한후 redirection 단계에서 무한 루프에 빠지는 현상이 발생합니다.
> INFO: 127.0.0.1:49371 - "GET /votes/create HTTP/1.1" 303 See Other
> INFO: 127.0.0.1:49371 - "GET /votes/create HTTP/1.1" 303 See Other
> ...
> 이유를 분석하시오. manager인지 검증 된 후 /votes/create가 활성화 되야 하지만 계속 redirection을 발생시킵니다."
