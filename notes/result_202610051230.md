## 2. Dockerfile 주요 명세 검증

### 2.1 Persistent Volume 연동 (`DATA_PATH`)
```dockerfile
ENV DATA_PATH=/app/data
VOLUME ["/app/data"]
```
- 컨테이너 내부의 `/app/data` 디렉터리에 SQLite DB(`vote_event.db`)와 업로드 이미지(`uploads/covers`, `uploads/items`)가 함께 저장됩니다.
- 호스트의 디렉터리를 `-v ./data:/app/data`로 연결하면 컨테이너가 삭제되거나 재생성되어도 모든 데이터가 안전하게 보존됩니다.

### 2.2 노출 포트 및 DEFAULT_PREFIX
```dockerfile
EXPOSE 5000
ENV DEFAULT_PREFIX=/votes
```
- 기본 포트 5000번 노출
- 컨테이너 실행 시 `-e DEFAULT_PREFIX=/custom`으로 변경 가능하며, 변경된 prefix는 웹 애플리케이션 전체 라우팅과 헬스체크에 자동 반영됩니다.

### 2.3 컨테이너 헬스체크 (HEALTHCHECK)
```dockerfile
HEALTHCHECK --interval=30s --timeout=10s --retries=3 --start-period=5s \
    CMD python -c "import os, requests; prefix = os.getenv('DEFAULT_PREFIX', ''); requests.get(f'http://localhost:5000{prefix}/api/status')"
```
- 요청 사양에 맞춰 `requests` 라이브러리를 통해 컨테이너 내부에서 주기적으로 `{DEFAULT_PREFIX}/api/status`에 핑을 보내며 상태를 검증합니다.
- 응답 JSON:
```json
{
  "status": "ok",
  "app": "VoteEvent",
  "prefix": "/votes",
  "database": "connected"
}
```

### 2.4 시작 커맨드 (CMD)
```dockerfile
# Gunicorn 운영서버로 기동 (요청한 사양에 맞춘 최적화 워커 및 디버깅 로그 옵션)
CMD ["gunicorn", "-k", "uvicorn.workers.UvicornWorker", "--bind", "0.0.0.0:5000", "--workers", "2", "--log-level", "debug", "--access-logfile", "-", "--error-logfile", "-", "--capture-output", "main:app"]

# 대안: Uvicorn 직접 실행 시 아래 커맨드로 교체 가능
# CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "5000"]
```
- 요청된 2가지 옵션을 완벽히 수용하여, 기본적으로 워커 2개의 Gunicorn 프로덕션 서버로 기동되도록 구성하였으며 주석을 통해 Uvicorn 직접 실행으로도 쉽게 전환할 수 있도록 구현하였습니다.
