## 2. 요구사항 상세 분석 및 도메인 해석

### 2.1 `.env` 환경변수 로드 및 하드코딩된 외부 엔드포인트 제거
1. **현황 및 문제점**:
   - 프로젝트 루트의 [`.env`](file:///C:/Dev/python/voteEvent/.env) 파일에는 다음 변수들이 정의되어 있음:
     - `DEFAULT_PREFIX=/votes`
     - `AUTH_URL=https://holyseeds.thewayworks.net/auth`
     - `AUTH_VERIFY_URL=${AUTH_URL}/api/verify-session`
     - `VDSTREAM_URL=https://holyseeds.thewayworks.net/vdstream`
     - `FOTOSTREAM_URL=https://holyseeds.thewayworks.net/fotostream`
   - 그러나 [`app/core/config.py`](file:///C:/Dev/python/voteEvent/app/core/config.py)에서 `.env` 파일을 읽는 로더(`python-dotenv` 또는 자체 파서)가 없어, 로컬 실행 시 `.env`의 설정값 및 `${AUTH_URL}`과 같은 변수 치환(Interpolation)이 제대로 반영되지 않을 위험이 있음.
   - 또한 `.env`에는 `VDSTREAM_URL`로 선언되어 있으나 [`app/core/config.py`](file:///C:/Dev/python/voteEvent/app/core/config.py)에서는 `VDSTREAM_BASE_URL`만 찾고 있으며, `FOTOSTREAM_URL`은 아직 정의되어 있지 않음.
   - [`app/templates/base.html`](file:///C:/Dev/python/voteEvent/app/templates/base.html) 및 [`app/templates/admin/event_list.html`](file:///C:/Dev/python/voteEvent/app/templates/admin/event_list.html) 등 템플릿 내부에 `'https://holyseeds.thewayworks.net/auth'` 및 `'https://holyseeds.thewayworks.net/auth/api/verify-session'` 문자열이 폴백 형태로 하드코딩되어 있음.
   - [`Dockerfile`](file:///C:/Dev/python/voteEvent/Dockerfile) 및 [`docker-compose.yml`](file:///C:/Dev/python/voteEvent/docker-compose.yml)에도 `VDSTREAM_URL`, `FOTOSTREAM_URL`, `AUTH_VERIFY_URL` 환경변수 선언을 일관되게 동기화해야 함.
2. **해결 방향**:
   - `app/core/config.py` 최상단에서 `.env` 파일을 직접 파싱하거나 `dotenv`를 통해 로드하고, `${VAR}` 형태의 환경변수 참조 구문(`AUTH_VERIFY_URL=${AUTH_URL}/api/verify-session`)을 동적으로 확장(Interpolation)하도록 구현.
   - `AUTH_URL`, `AUTH_VERIFY_URL`, `VDSTREAM_URL` (하위호환 별칭 `VDSTREAM_BASE_URL` 유지), `FOTOSTREAM_URL` (하위호환 별칭 `FOTOSTREAM_BASE_URL`)을 표준 환경변수로 구성.
   - [`app/core/templates.py`](file:///C:/Dev/python/voteEvent/app/core/templates.py)의 Jinja2 전역 변수(`templates.env.globals`)에 `auth_url`, `auth_verify_url`, `vdstream_url`, `fotostream_url`을 모두 등록하고, HTML/JS 템플릿 내의 하드코딩된 도메인 문자열을 제거하여 환경변수 기반으로만 동작하도록 일원화.

### 2.2 이벤트 다중 사진 지원 옵션 (`allow_multi_photo`)
1. **이벤트 설정 레벨**:
   - 이벤트를 생성/수정할 때 관리자 폼([`app/templates/admin/event_form.html`](file:///C:/Dev/python/voteEvent/app/templates/admin/event_form.html))에서 **"다중 사진 등록 지원 (`allow_multi_photo`)"** 옵션을 제공하거나, 항목 생성 시 다중 사진 등록 모드를 지원.
   - 이벤트 모델(`Event`)에 `allow_multi_photo` (Boolean, 기본값 `True` 또는 체크박스 선택) 컬럼을 추가하고, 기존 DB 자동 마이그레이션(`init_db()`)에 반영.
   - 다중 사진 지원이 활성화된 이벤트에서는 참여자가 사진 등록 시 **2장 이상(최대 49장)**의 사진을 한 번에 선택/추가하여 업로드할 수 있으며, 항목 등록 모달에서도 단일/다중 사진 안내 및 다중 파일 선택(`multiple`)을 지원. (비활성화 시 기존처럼 단일 사진 1장 또는 영상 1개만 등록)

### 2.3 사진 등록 장수에 따른 분기 처리 (1장 vs 2~4장 다중 사진 vs 5장 이상 FOTOSTREAM 영상 변환)
1. **Case A: 1장 등록 (단일 사진)**:
   - 기존과 동일하게 1920px 리사이징 및 WebP 최적화 후 `media_type="image"`, `image_path`에 저장.
2. **Case B: 2장 ~ 4장 등록 (다중 사진 프리뷰 & 개별 선택 상세보기)**:
   - 각 사진을 1920px 리사이징 및 WebP 최적화하여 저장 (`image_path`에 대표 1번 이미지 저장, `image_paths` JSON 컬럼에 전체 이미지 경로 배열 `["items/a.webp", "items/b.webp", ...]` 저장).
   - **카드 항목 프리뷰 영역**:
     - 등록된 2~4장의 사진을 카드 썸네일 영역(`aspect-[4/3]`) 안에서 **한번에 볼 수 있도록** 분할 그리드(Collage Grid) 레이아웃으로 렌더링:
       - **2장**: 좌우 2분할 (`grid-cols-2`)
       - **3장**: 좌측 1장(크게) + 우측 상하 2장 또는 3분할 그리드
       - **4장**: $2 \times 2$ 4분할 그리드 (`grid-cols-2 grid-rows-2`)
     - 우측 하단 또는 좌측 상단에 `사진 N장` 배지 표시.
   - **상세보기 모달 (`detail-modal`)**:
     - 메인 뷰어 영역 하단(또는 좌우 네비게이션 + 하단 썸네일 스트립)에 등록된 2~4장의 미니 썸네일 목록을 표시.
     - 사용자가 썸네일을 **한 장씩 클릭/선택하거나 좌우 화살표 버튼**을 눌러 선택한 사진을 메인 뷰어에서 고화질 **전체보기(원본 비율)**로 감상할 수 있도록 지원.
3. **Case C: 5장 이상 등록 (최대 49장, FOTOSTREAM 연동 동영상 스트림 자동 변환)**:
   - 사용자가 사진을 **5장 이상** 선택하여 업로드하면, [`fotostream_api.md`](file:///C:/Dev/python/fotostream/fotostream_api.md) 명세에 따라 **FOTOSTREAM API (`{FOTOSTREAM_URL}/api/v1/...`)**를 호출하여 이미지들을 슬라이드쇼/줌인 매트릭스 동영상(HLS/MP4)으로 변환.
   - **FOTOSTREAM API 연동 규격 (`fotostream_api.md` 기반)**:
     - 작업 등록: `POST {FOTOSTREAM_URL}/api/v1/jobs` (`multipart/form-data`: `images` 다중 바이너리, `title`, `resolution="1080p"`, 선택적 `bgm_id` / `bgm_file`) -> `202 Accepted` (`job_id`, `status: "QUEUED"`).
     - 진행 상태 폴링: `GET {FOTOSTREAM_URL}/api/v1/jobs/{job_id}` -> `status` (`QUEUED` -> `PROCESSING` -> `COMPLETED` / `FAILED`), `progress` (0~100%), 완료 시 `video_id` 반환.
     - 비디오 메타데이터 및 스트림 URL 획득: `GET {FOTOSTREAM_URL}/api/v1/videos/{video_id}` -> `hls_url` (`/fotostream/api/v1/videos/{video_id}/hls/playlist.m3u8`), `stream_url` (`/fotostream/api/v1/videos/{video_id}/stream`), `thumbnail_url`, `duration`, `resolution`.
     - 비디오 삭제: 항목 삭제 또는 이벤트 삭제 시 `DELETE {FOTOSTREAM_URL}/api/v1/videos/{video_id}` 호출하여 원격 리소스 정리.
   - **표시 및 재생 동작**:
     - 변환 완료된 항목은 `media_type="fotostream"` (또는 `media_type="video"` + 소스 구분 / `video_source="fotostream"`)으로 저장하며, 대표 썸네일(첫 번째 사진 또는 fotostream 썸네일)과 `video_id`, `video_stream_url` (HLS `.m3u8` URL 및 MP4 fallback URL)을 저장.
     - 카드 항목 및 모아보기에서는 동영상 스트림 프리뷰(호버 시 재생 또는 HLS/MP4 미리보기 + `포토스트림 영상 (N장)` 배지)를 제공.
     - 상세보기 모달에서는 `Hls.js` (및 네이티브 HLS / MP4 fallback)를 통해 FOTOSTREAM HLS 스트림을 즉시 재생(VDSTREAM과 달리 별도의 5슬롯 제한 세션/하트비트가 불필요하며, `fotostream`의 무버퍼링 HLS 플레이리스트 직접 스트리밍 또는 프록시/절대 URL 재생).
