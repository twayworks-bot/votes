# 사용자 요구사항 정의서 (req_202610112256.md)

- **작성 일시**: 2026-10-11 22:56
- **문서 목적**: 로컬호스트(`localhost`) 개발 환경에서 "관리자 로그인" 실행 시 `403 Forbidden` (`GET /votes/create?auth_attempted=1`) 발생하는 원인을 분석하고, 웹 스크립트(Client-side JS)에서 원격 Keycloak 세션(`https://holyseeds.thewayworks.net/auth/api/verify-session`)을 직접 검증하여 로컬 백엔드와 세션을 동기화하는 사용자 요구사항 기록

## 1. 사용자 원본 요구사항 (User Raw Request)

> "localhost에서 서비스를 실행 중 "관리자 로그인 "을 실행하면, 다음과 같이 에러가 발생합니다.
> "GET /votes/create?auth_attempted=1 HTTP/1.1" 403 Forbidden
> 
> 만약, https://holyseeds.thewayworks.net/auth/api/verify-session 를 통해 결과를 얻으면, 
> ```
> {"valid":true,"is_manager":true,"is_super":true,"role_flag":"2","roles":["user","manager","admin","super","super_admin"],"has_required_role":true,"user":{"id":"4a354343-1b24-4295-82a6-1c2b6e253005","username":"01055787363","name":"양인창","email":"plus.holyseeds@gmail.com"}}
> ```
> 를 얻습니다. 
> session 검증 방법에 문제가 있는 것 같습니다. 
> python 서비스가 아닌 web 스크립트 코드에서 실행하여 가져와야 하는 것 같습니다. 
> 확인해 주세요."

## 2. 문제 원인 정밀 분석 (Root Cause Analysis)

### 2.1 도메인 간 브라우저 쿠키 격리 (Cross-Origin Cookie Isolation)
- 사용자가 원격 사이트(`https://holyseeds.thewayworks.net`)에 이미 로그인되어 있어 브라우저에는 원격 도메인 전용 쿠키(`auth_session`)가 보관되어 있습니다.
- 그러나 사용자가 로컬호스트(`http://localhost:5000`)에서 파이썬 백엔드로 요청을 보낼 때, 웹 브라우저의 동일 출처 정책(Same-Origin Policy 및 Cookie Domain 스코프)에 따라 **`holyseeds.thewayworks.net`의 쿠키는 로컬호스트 백엔드로 전송되지 않습니다.**
- 따라서 파이썬 백엔드(FastAPI)가 서버 사이드에서 `verify_admin_session(auth_session)`을 실행하려 해도 `auth_session` 값이 `None`이므로 항상 비인증 상태로 판정됩니다.
- 이로 인해 1차 리다이렉트 후 복귀 시에도 세션이 없어 무한 루프 차단 가드(Loop Breaker)가 발동되어 `403 Forbidden (?auth_attempted=1)`이 발생하게 됩니다.

### 2.2 웹 스크립트(Client JS) 직접 검증의 원리
- 반면 브라우저 클라이언트 스크립트가 `AUTH_VERIFY_URL`(`https://holyseeds.thewayworks.net/auth/api/verify-session`)로 직접 `fetch(..., { credentials: 'include' })`를 호출하면, 브라우저가 원격 도메인의 쿠키를 자동으로 함께 전송하므로 원격 서버는:
  ```json
  {"valid":true,"is_manager":true,"is_super":true,"role_flag":"2","roles":["user","manager","admin","super","super_admin"],"has_required_role":true,"user":{"id":"...","username":"01055787363","name":"양인창","email":"plus.holyseeds@gmail.com"}}
  ```
  결과를 정상적으로 반환합니다.

### 2.3 해결 요구사항 및 아키텍처
1. **웹 스크립트 직접 검증 및 로컬 백엔드 세션 동기화**:
   - 웹 브라우저 스크립트(`base.html`)에서 `AUTH_VERIFY_URL`을 `credentials: 'include'`로 직접 비동기 호출.
   - 응답이 `valid === true && is_manager === true`이면, 즉시 로컬 백엔드의 세션 동기화 엔드포인트(`POST /votes/api/auth/sync-session`)로 검증 결과를 전달.
   - 로컬 백엔드는 이를 수신하여 `localhost` 도메인에 대한 유효한 관리자 세션 쿠키(`auth_session` 및 서명 토큰)를 브라우저에 구워줌(`Set-Cookie`).
2. **관리자 페이지 진입 보장**:
   - 로컬 백엔드가 `localhost` 쿠키를 발급받은 후 `window.location.href = targetPath` (예: `/votes/create`)로 이동하므로, 백엔드의 `require_manager_web` 의존성 검증이 100% 정상 통과되어 403 에러가 해결됨.
3. **403 페이지 자가 치유(Self-Healing) 브릿지 탑재**:
   - 직접 URL로 접속하여 로컬 쿠키가 없는 상태에서 403 화면이 노출되더라도, 403 화면 스크립트가 원격 `verify-session`을 자동 호출하여 관리자 확인 시 로컬 세션 동기화 후 원래 페이지로 자동 복구(`reload`).
