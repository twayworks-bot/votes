## 1. 개요 및 목적

## 3. 원인 분석 및 해결 상세

### 3.1 원인 (Root Cause)
- `/votes/{eventName}`을 담당하는 [app/routers/event_view_router.py](file:///C:/Dev/python/voteEvent/app/routers/event_view_router.py)의 `view_event_page`에서 템플릿 context에 `auth_url`, `login_url`을 전달하지 않았음.
- Jinja2 템플릿 [app/templates/base.html](file:///C:/Dev/python/voteEvent/app/templates/base.html)에서 `auth_url ~ '/login?redirect=...'` 평가 시 `auth_url`이 빈 문자열(`""`)로 처리되어 결과가 `"/login?redirect=..."`로 렌더링됨.

### 3.2 개선 조치
1. **공통 템플릿 환경 전역 주입**:
   - [app/core/templates.py](file:///C:/Dev/python/voteEvent/app/core/templates.py)에서 `templates.env.globals["auth_url"] = AUTH_URL`로 기본 등록하여 템플릿 어디서나 기본값 보장.
2. **서브패스 뷰어 인증 컨텍스트 전달**:
   - [app/routers/event_view_router.py](file:///C:/Dev/python/voteEvent/app/routers/event_view_router.py)에서 현재 요청자의 세션을 검증하고, 현재 페이지 복귀용 `login_url`을 생성하여 주입.
3. **템플릿 폴백 이중 방어**:
   - `{% set safe_auth = auth_url if auth_url else 'https://holyseeds.thewayworks.net/auth' %}` 선언을 통해 `/auth` prefix가 어떠한 상황에서도 절대 유실되지 않도록 보장.
   - "새 이벤트 개설" 버튼 클릭 시에는 항상 `/votes/create` 진입 권한 획득 목적의 로그인 게이트웨이 주소를 전달하도록 분리.
