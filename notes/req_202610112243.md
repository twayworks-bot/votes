## 1. 사용자 원본 요구사항 (User Raw Request)

> "다음과 같이 "새 이벤트 개설"에 대한 login 인증을 할 때, 
> "https://holyseeds.thewayworks.net/auth/login?redirect=/votes/create&require_role=manager" 와 같이
> 검증과 동시에 버튼을 실행하면, local 개발 서비스 상태에서는 로그인 상태를
> 확인하기 어렵고 다시 localhost로 redirection이 되지 않는 문제가 있습니다.
> local 테스트의 경우 원격서버에 로그인이 되어 있으면 사전 검증 절차로  redirection URL을 통해 검증을 하지 않도록
> 수정이 필요합니다.
> 즉,  사전에 내부 시스템에서 "verify_admin_session" (https://holyseeds.thewayworks.net/auth/api/verify-session) 인증검증을 한번 하고,
>  인증 세션이 검증된 상태이면,
> 바로 "/votes/create"를 부르고 인증이 안된 상태이면 
> "https://holyseeds.thewayworks.net/auth/login?redirect=/votes/create&require_role=manager"를 호출하도록 수정이 필요합니다.
> 다른 관리자 호출 버튼의 경우도 동일하게 관리자검증("verify_admin_session" ) 후   버튼 redirection 여부를 확인 후 분기하시오.
> 
> Dockerfile 내부 환경 변수를 참고 하여 수정하시오.
> ENV AUTH_URL=https://holyseeds.thewayworks.net/auth
> ENV AUTH_VERIFY_URL=${AUTH_URL}/api/verify-session"

## 2. 문제 배경 및 요구사항 심층 분석 (Root Cause & Requirements Analysis)

### 2.1 기존 인증 흐름의 문제점
1. **로컬 개발 환경(`localhost:8000`)과 원격 인증 도메인(`holyseeds.thewayworks.net`)의 도메인 격리**:
   - 사용자가 원격 Keycloak에 이미 로그인되어 있어도, 해당 세션 쿠키(`auth_session`)는 `holyseeds.thewayworks.net` 도메인 스코프로 발급되어 `localhost` 요청 시 브라우저가 자동으로 전송하지 않습니다.
   - 따라서 로컬에서 "새 이벤트 개설" 버튼(`GET /votes/create`)을 누르면 백엔드는 세션 쿠키 부재로 Keycloak 로그인 페이지로 303 Redirect를 발생시킵니다.
2. **원격 로그인 리다이렉트 시 상대 경로 전송 문제**:
   - `redirect=/votes/create`와 같이 상대 경로를 그대로 보내면 원격 Keycloak에서 로그인 성공 후 원격 도메인(`https://holyseeds.thewayworks.net/votes/create`)으로 복귀하게 되어, 로컬 개발 인스턴스로 복귀되지 않는 문제가 발생합니다.
3. **무한 303 리다이렉션 루프 현상**:
   - 브라우저 쿠키 미전송 상태에서 무조건 서버 엔드포인트를 호출하면 [로컬 303 -> Keycloak 302 -> 로컬 303]의 핑퐁 루프가 발생합니다.

### 2.2 해결 요구사항 및 설계 방향
1. **Dockerfile 환경변수 표준화 및 코드 동기화**:
   - Dockerfile에 `ENV AUTH_VERIFY_URL=${AUTH_URL}/api/verify-session` 선언을 명시하고,
   - 애플리케이션 설정(`app/core/config.py`)에서 `AUTH_VERIFY_URL`을 우선 읽고 누락 시 기본값(`${AUTH_URL}/api/verify-session`)을 사용하도록 구현.
2. **클라이언트 사전 검증(Pre-verification) 파이프라인 구축**:
   - 관리자 전용 액션(새 이벤트 개설, 이벤트 수정, 이벤트 삭제, 관리자 로그인 등) 버튼 클릭 시, 바로 타겟 URL로 이동하거나 원격 Keycloak으로 무조건 이동하지 않음.
   - 사전 검증 엔드포인트(`GET /votes/api/auth/status`)를 비동기 호출(`fetch`)하여 현재 세션의 매니저 권한(`is_manager`)을 선제적으로 검증.
   - **검증 성공(`is_manager === true`) 시**:
     - 현재 세션 토큰을 브라우저 쿠키(`auth_session`)에 자동 주입/동기화한 후 타겟 URL(예: `/votes/create`, `/votes/events/{id}/edit` 등)로 직접 즉시 이동. 원격 Keycloak을 경유하지 않음.
   - **미인증 또는 권한 부족 시**:
     - 원격 Keycloak 로그인 URL(`AUTH_URL + /login?redirect=...&require_role=manager`)로 안내하되, `window.location.origin`을 포함한 완전한 URL을 전달하여 로컬 개발 환경에서도 로그인 후 본래 로컬 주소로 정확히 복귀하도록 보장.
3. **모든 관리자 호출 버튼의 일관된 분기 처리**:
   - 네비게이션 바 "새 이벤트 개설" 버튼
   - 이벤트 목록 상단 및 빈 화면 "새 이벤트 개설" 버튼
   - 이벤트 카드별 "수정" 버튼
   - 이벤트 카드별 "삭제" 버튼
   - 비인증 상태 "관리자 로그인" 버튼
   모두 통합 사전 검증 핸들러(`handleManagerAction`)를 통해 실행되도록 표준화.
