# 사용자 원본 요구사항 및 계획서 (2026-10-05 21:06)

## 1. 사용자 원본 요구사항

```text
BASEURL(/PREFIX) 아래 eventName을 붙였서 link를 이동한 경우,
예로 /votes/bazaarposter에서 "관리자 로그인"과 "새 이벤트 개설" 버튼을 클릭하면,
/auth/login으로 이동해야 하는데, '/auth'에 해당하는 APP name prefix가 삭제된 채 전달되고 있습니다.
이유를 검토 해주세요. 

실제로 로컬테스트 시 "http://localhost:5000/votes/bazaarposter"에서 "관리자 로그인"버튼과 "새 이벤트 개설"버튼에서 
링크 오류가 있습니다.
```

---

## 2. 문제 원인 분석 (Root Cause Analysis)

1. **템플릿 컨텍스트 누락**:
   - `/votes/bazaarposter`를 처리하는 `event_view_router.py`의 `view_event_page` 핸들러에서 Jinja2 템플릿 `event/detail.html`로 context를 넘겨줄 때 `auth_url`, `login_url`, `is_manager`, `user` 등이 전달되지 않음.
2. **Jinja2 문자열 결합 시 빈 문자열 처리**:
   - `base.html` 상단 네비게이션에서:
     `{{ login_url or (auth_url ~ '/login?redirect=' ~ default_prefix ~ '/create&require_role=manager') }}`
   - `login_url`과 `auth_url`이 컨텍스트에 없으므로 `auth_url`은 빈 문자열(`""`)로 치환됨.
   - 따라서 `"" ~ "/login?..."` -> `"/login?redirect=..."`가 렌더링되어 `/auth` 애플리케이션 prefix가 누락된 채 호스트 루트의 `/login`으로 링크되는 오류 발생.
3. **근본적 해결책**:
   - Jinja2 템플릿 환경(`templates.env.globals`)에 `AUTH_URL`과 `DEFAULT_PREFIX`를 전역 기본값으로 등록하여 모든 템플릿 렌더링 시 기본 주입 보장.
   - `event_view_router.py`에서도 `verify_auth_session(request)`를 호출하여 사용자의 로그인 상태(`is_manager`, `user`) 및 정확한 콜백 주소가 포함된 `login_url`, `logout_url`을 컨텍스트에 명시적 전달.
   - `base.html`의 폴백(Fallback) 식에서도 `auth_url`이 없을 경우 최소 `AUTH_URL` 또는 `/auth`가 유지되도록 방어 코드 적용.

## 3. 개발 실행 계획

1. **Jinja2 전역 환경변수 등록**:
   - `admin_router.py`, `event_view_router.py` 등의 `templates` 객체에 `AUTH_URL`, `DEFAULT_PREFIX` 전역 등록 (또는 공통 템플릿 헬퍼 모듈 마련).
2. **`event_view_router.py` 업데이트**:
   - `verify_auth_session(request)` 호출 및 `auth_info`, `user`, `is_manager`, `auth_url`, `login_url`, `logout_url` 컨텍스트 주입.
   - 404 페이지 템플릿 응답 시에도 기본 인증/경로 컨텍스트 주입.
3. **`base.html` 템플릿 보강**:
